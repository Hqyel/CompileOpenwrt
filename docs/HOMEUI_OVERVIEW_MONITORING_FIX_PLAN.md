# HomeUI 系统概况监控修正计划

## 1. 背景

`luci-theme-homeui` 在系统概况页面中增加了以下监控内容：

- WAN 信息卡片中的当前速率和迷你曲线；
- 上下行速率图表；
- 终端数量图表；
- 内存使用率图表；
- 1 小时和 24 小时范围切换。

当前实现存在以下问题：

1. 设备计数器来自 LuCI `network` 模块缓存，主题的 3 秒轮询并
   不等于每 3 秒获取了新计数器。
2. 所谓“平均值”实际上是当前时间桶的最后一个瞬时值。
3. 历史数据由当前值复制或人工乘以波动系数生成，不是真实
   采样。
4. 历史仅保存在浏览器 `localStorage` 中，关闭页面后不再采集。
5. WAN 卡片和大图使用两套不同的接口选择状态。
6. 选中接口速率为 `0` 时，代码会回退到全部接口速率，导致
   显示其他接口的流量。
7. 类似 `wan` 和 `wan6` 的逻辑网络可能共用同一个 L3 设备，
   当前列表没有去重。
8. 全部接口累加会重复统计 WAN、LAN、VLAN、PPPoE 和隧道中的
   同一批转发流量。

## 2. 修正目标

### 2.1 必须达成

- 当前速率来自真实设备计数器，不再依赖过期的 `network`
  模块缓存。
- WAN 卡片和上下行大图使用同一个接口选择。
- 速率为 0 B/s 时显示真实的零，不回退到其他接口数据。
- 所有曲线只由真实采样生成，不创造人工波动。
- 平均值和峰值按实际采样计算。
- 数据缺失时显示空缺或“正在采集”，不显示伪造历史。

### 2.2 不属于本次首要目标

- 不要在第一阶段引入复杂的数据库。
- 不要为了保留跨重启历史而高频写入路由器闪存。
- 不把浏览器 `localStorage` 当作权威监控数据源。
- 不在数据源未修正前增加更多图表配置项。

## 3. 总体设计

将监控分为“实时数据”和“历史数据”两条独立链路。

```text
实时数据
luci.getRealtimeStats("interface", deviceName)
                  |
                  v
按后端时间戳计算速率
                  |
                  +----> WAN 卡片当前值
                  +----> WAN 卡片迷你曲线
                  +----> 实时速率大图

历史数据
路由器后台采集器
                  |
                  v
/tmp 或进程内存中的环形缓冲区
                  |
                  v
ubus/RPC 查询
                  |
                  +----> 1 小时图表
                  +----> 24 小时图表
```

## 4. 实时速率数据源

### 4.1 使用 LuCI 实时统计 RPC

速率数据应改为：

```js
callRealtimeStats('interface', deviceName)
```

该 RPC 返回带时间戳的接口计数器序列。应使用相邻两个后端
样本的时间差和计数器差计算速率，不再使用浏览器轮询时间差。

建议保留 3 秒默认轮询周期，与 LuCI 官方实时带宽页保持一致。

### 4.2 接口实时状态

用设备名作为统计键，不用数组下标。

```js
interfaceStats[deviceName] = {
  timestamp: 0,
  rxBytes: 0,
  txBytes: 0,
  rxBps: 0,
  txBps: 0,
  samples: []
};
```

`0` 必须作为有效值处理。只有字段不存在或 RPC 请求失败时，
才进入“无数据”状态。

### 4.3 计数器异常处理

必须处理：

- 网络接口重启后计数器归零；
- 设备被删除或更名；
- RPC 请求超时；
- 时间戳重复或倒退；
- 数值为负数或明显超过接口可能速率；
- 连续请求重叠。

异常样本应丢弃并重置基准，不应绘制成速率尖峰。

## 5. WAN 接口选择与图表联动

### 5.1 统一选择状态

将当前的：

- `liveState.selectedWanIdx`；
- `chartState.rateIface`。

合并为一个稳定状态：

```js
selectedWan = {
  networkNames: ['wan', 'wan6'],
  deviceName: 'eth1'
};
```

用户在 WAN 信息卡片中切换接口后，同时更新：

- WAN IP；
- 协议和上级网关；
- 运行时间；
- 累计流量；
- 当前上下行速率；
- 迷你速率曲线；
- 上下行速率大图；
- 大图图例和历史查询目标。

建议把当前的“点击循环切换”改为明确的下拉菜单，使用户能看到
可选接口和当前选择。

### 5.2 逻辑网络与统计设备去重

接口列表应优先使用 LuCI 的 WAN/WAN6 网络识别能力，而不是只按
名称是否以 `wan` 开头判断。

多个逻辑网络映射到同一个 L3 设备时，应合并为一个统计项。
例如：

```text
wan / wan6 (eth1)
```

这是因为设备字节计数器无法区分共享设备上的 IPv4 和 IPv6
流量。

### 5.3 “全部 WAN”的定义

如果保留“全部”选项，它应表示：

- 所有去重后的上游 WAN L3 设备；
- 不包含 LAN 设备；
- 不同时累加物理设备和其 VLAN/PPPoE 中间层；
- 每个时间点在统一时间轴上聚合。

## 6. WAN 卡片迷你曲线

### 6.1 初始状态

迷你曲线必须从进入页面后的真实采样开始生成，不应在首次
渲染时填充一条完整曲线。

具体行为：

1. 尚无样本时，显示空坐标或“正在采集”。
2. 获得第一个样本后，只绘制一个点。
3. 获得第二个样本后，开始绘制线段。
4. 之后每次真实采样追加一个点。
5. 样本达到上限后，删除最旧点并向左滚动。

如果保留 20 个点并每 3 秒采样一次，迷你曲线将在约 57 秒后
自然填满。

### 6.2 零速率的绘制

真实样本为 0 B/s 时，点应位于基线上。不应为了让界面看起来
在动而添加正弦波、随机抖动或最小高度。

可以保留颜色、渐变和平滑插值，但插值只能改变相邻真实样本之间的
视觉过渡，不能改变样本数值。

### 6.3 切换接口时的行为

建议为每个去重后的 WAN 设备保留独立的页面内实时缓冲区。

- 切换到已有样本的接口时，显示该接口自进入页面以来的真实曲线。
- 切换到尚未采样的接口时，从空曲线开始。
- 不得回退显示“全部接口”或上一个接口的曲线。

如果 WAN 数量很少，可每 3 秒并行采样所有去重后的 WAN 设备，
使切换时能立即显示已收集的真实曲线。

## 7. 大图表实时模式

在没有路由器端历史服务之前，大图应改成明确的实时窗口。

建议：

- 保留最近 120 个 3 秒样本，约为 6 分钟；
- 横轴使用样本的真实时间戳；
- 初始时不用零值填满整张图；
- 当前值、平均值和峰值均从当前实时窗口计算；
- 页面重新加载后实时窗口重新开始。

如果还没有历史后端，应暂时移除或禁用“1 小时”和“24 小时”
按钮，避免对用户造成误导。

## 8. 真实历史数据

### 8.1 为什么不应由浏览器保存

浏览器历史有以下固有限制：

- 只在页面打开时采集；
- 不同浏览器的数据不一致；
- 清理缓存后数据丢失；
- 电脑休眠、切换页面或后台限流会产生大量空洞；
- 浏览器无法代表路由器自身的连续运行状态。

因此，`localStorage` 只能保存界面偏好，不保存权威监控历史。

### 8.2 推荐的路由器端环形缓冲区

建议新增轻量采集服务，但不将服务逻辑耦合到主题渲染中。可将其
设计为独立包，例如 `homeui-stats` 或 `luci-app-homeui-monitor`。

推荐聚合粒度：

| 范围 | 时间桶 | 数量 | 用途 |
|---|---:|---:|---|
| 实时 | 5 秒 | 120 | 最近 10 分钟 |
| 1 小时 | 1 分钟 | 60 | 短期趋势 |
| 24 小时 | 5 分钟 | 288 | 全天趋势 |

每个时间桶至少保存：

```text
startTime
sampleCount
sum
maximum
last
```

其中：

- 平均值为 `sum / sampleCount`；
- 峰值为 `maximum`；
- 没有样本的时间桶为 `null`，不用 0 代替；
- 图表对 `null` 显示断线或空白。

数据建议保存在 `/tmp` 或采集进程内存中，避免高频写入闪存。
路由器重启后，重启前时间段显示为空缺，不补造数据。

### 8.3 采集指标

后台服务可按以下频率采集：

| 指标 | 建议采样周期 | 说明 |
|---|---:|---|
| WAN RX/TX | 5 秒 | 按去重后的 L3 设备保存 |
| 内存使用率 | 5 秒 | 来自 `system.info` |
| 无线终端数 | 15 秒 | 使用实际关联客户端 |
| 有线终端数 | 15～30 秒 | 需要先定义“在线”语义 |

“DHCP 租约数”和“在线终端数”不是同一个概念。修正时应明确终端
图表统计的是：

- 当前可达邻居；
- 活动 DHCP 租约；
- 无线关联数；
- 或上述数据的去重合并。

界面文案必须与最终语义一致。

## 9. 轮询与刷新间隔

### 9.1 默认频率

不同数据不应继续共用一个 3 秒轮询：

| 数据 | 建议页面刷新周期 |
|---|---:|
| 当前 WAN 速率 | 3 秒 |
| 当前内存 | 5 秒 |
| 终端状态 | 15～30 秒 |
| WAN IP、网关和接口列表 | 30 秒 |
| 型号、固件和内核信息 | 页面加载时一次 |

所有轮询都应：

- 防止同一任务的前一个请求未完成时再次发起；
- 在请求完成后计划下一次执行；
- 页面进入后台时降低频率或暂停；
- 恢复到前台时立即刷新；
- 失败时保留上一个有效值并显示数据已过期，不伪造新样本。

### 9.2 是否提供用户设置

第一版不增加刷新间隔设置。

原因：

- 刷新间隔不能解决数据源和历史存储问题；
- 更短的间隔会增加 rpcd 和低性能设备负担；
- 当后端没有新样本时，更快刷新也无法产生新数据。

可先在界面中显示固定文案：

```text
实时 · 每 3 秒更新
```

如后续确有需求，只提供 `3 / 5 / 10 秒` 三个预设。该设置只影响
前端实时刷新，不影响后台历史采集周期。

## 10. 分阶段实施

### 阶段 A：移除伪数据

- 删除历史序列的波动系数填充。
- 删除迷你曲线的人工正弦波。
- 删除终端数、连接数和内存的固定回退值。
- 无数据时显示 `--` 或“正在采集”。
- 在没有历史后端时暂时隐藏 1 小时和 24 小时按钮。

### 阶段 B：修正实时数据

- 使用 `getRealtimeStats('interface', deviceName)`。
- 用 RPC 返回时间戳计算 RX/TX 速率。
- 为每个 WAN 设备维护独立实时样本队列。
- 将 WAN 卡片与速率大图的接口选择合并。
- 对共用 L3 设备的逻辑网络去重。
- 修正零值回退和全部接口重复累加。

### 阶段 C：修正迷你曲线和实时大图

- 迷你曲线从第一个真实样本开始逐点生成。
- 大图从空状态开始，显示页面打开后的实时窗口。
- 用真实样本计算当前、平均和峰值。
- 根据真实时间戳生成横轴。
- 切换接口时只显示对应接口的样本。

### 阶段 D：引入可选历史后端

- 新增独立采集包和 procd 服务。
- 在 RAM 中维护 1 小时和 24 小时环形缓冲区。
- 通过只读 ubus/RPC 方法返回时间桶。
- 后端可用时启用 1 小时和 24 小时按钮。
- 后端不可用时自动回退到实时窗口，不伪造历史。

### 阶段 E：性能和稳定性

- 将快速、中速和慢速轮询拆分。
- 添加请求进行中标志。
- 后台页面降频。
- 对 RPC 错误显示轻量状态提示。
- 验证低性能 ARM 设备和 x86_64 设备的负载。

与纯前端主题强制绑定。

## 12. 验收标准

### 12.1 WAN 实时速率

- 空闲时 WAN 卡片和大图显示 0 B/s，曲线回到基线。
- 持续下载期间，页面下行速率与客户端观测值基本一致。
- 下载停止后，历史样本不会被后续零值覆盖掉。
- 不因 LAN 转发或 VLAN 中间层而重复计算。
- 接口重启不产生负速率或超大尖峰。

### 12.2 接口切换

- WAN 卡片和大图始终显示同一个选中设备。
- 选中空闲接口时，不显示其他接口流量。
- `wan` 和 `wan6` 共用设备时不重复统计。
- 接口顺序变化后，已选项不会错位。

### 12.3 曲线生成

- 首次进入页面时不显示伪造的完整曲线。
- 第一个真实样本到达后显示第一个点。
- 曲线随新样本逐步生成，填满后才开始滚动。
- 连续零速率显示水平基线，不出现人工抖动。
- 切换接口后不显示其他接口的历史。

### 12.4 真实历史

- 关闭浏览器后，后台采集仍继续运行。
- 重新打开页面后可加载关闭期间的真实数据。
- 无样本时间桶显示空缺，不补齐当前值。
- 平均值为实际算术平均，峰值为时间桶内最大真实样本。
- 默认不向闪存进行高频写入。

### 12.5 性能

- 不存在同一轮询任务的重叠请求。
- 页面后台状态下 RPC 频率显著降低。
- 终端、DHCP 和静态系统信息不再每 3 秒全量查询。
- 页面长时间打开后，样本数终端有上限，不持续增长。

## 13. 建议的首个交付边界

为了先解决当前用户可见的错误，首个交付建议包含阶段 A、B 和 C：

1. 实时速率正确；
2. WAN 接口选择全页联动；
3. 迷你曲线和大图从真实样本逐步生成；
4. 去除伪造历史和固定回退数据；
5. 暂时以“实时”代替不可靠的 1 小时/24 小时模式。

在该交付经过真实路由器流量测试后，再实施阶段 D 的后台历史服务。

## 15. 阶段 D 实施结果

阶段 D 采用随主题包安装的轻量级 `homeui-monitor` procd 服务：

- 安装或升级 `luci-theme-homeui` 时自动启用并启动服务；
- 每 5 秒采集网络设备累计 RX/TX 计数器和内存使用率；
- 每 15 秒采集有线 ARP 邻居与 hostapd 无线关联终端数量；
- 数据保存到 `/tmp/homeui-monitor`，页面关闭后仍继续采集；
- 后端每分钟保存平均值和峰值，每个接口最多保留约 24 小时；
- 前端按真实时间桶计算 1 小时和 24 小时图表；
- 卸载主题时停止服务并清除运行时历史文件。

历史数据使用内存文件系统，路由器重启后重新开始采集。这样不会对闪存
进行高频写入，也不需要用户额外安装独立采集包。

终端数量的后台统计口径为：

- 无线终端：hostapd 当前关联客户端；
- 有线终端：有效 IPv4 ARP 邻居，并排除已识别的无线客户端。
